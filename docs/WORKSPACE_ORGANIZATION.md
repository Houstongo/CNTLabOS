# Workspace Organization

## Root directory

Keep the project root focused on source code, entry scripts, and project docs.

Main working areas:

- `backend/`, `frontend/`, `src/`, `tools/`, `tests/`
- `docs/`, `data/`, `contexts/`
- root-level entry scripts such as `manage.py`

## Generated outputs

All large generated artifacts should live under `output/`:

- `output/batch_runs/`
  Batch processing outputs and comparison inputs.
- `output/manual_checks/`
  One-off test runs, visual checks, and temporary image outputs.
- `output/root_backups/`
  Backup files that used to sit in the root directory.
- `output/tmp_root/`
  Temporary root files, scratch exports, and ad hoc debug artifacts.

## Logs

Runtime logs that used to sit in the root directory are now stored in:

- `logs/root_runtime/`

Existing task-specific logs can continue to live under `logs/` or `reports/` when appropriate.

## Practical rule

If a file is generated by a script and is not part of the source tree, it should usually go into `output/` or `logs/`, not the project root.
