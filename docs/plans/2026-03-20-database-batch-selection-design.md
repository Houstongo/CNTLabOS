# Database Batch Selection Design

**Goal**

为主数据库列表页增加多选能力，让用户可以对选中图像批量执行图像表征算法和逻辑删除。

**Scope**

- 仅修改主数据库列表页，不改数据清洗页。
- 批量图像表征复用现有单条分析逻辑。
- 批量删除使用现有 `is_deleted` 逻辑删除语义。

**User Flow**

1. 用户在主数据库列表勾选一条或多条记录。
2. 列表头显示全选入口，顶部显示批量操作条和已选数量。
3. 用户可执行：
   - 批量图像表征
   - 批量逻辑删除
   - 清空选择
4. 操作完成后页面刷新，并给出成功/失败汇总。

**Frontend Design**

- 在主列表每行前加入复选框。
- 在表头加入“全选当前页”复选框。
- 在主页面头部动作区下方加入批量操作条。
- 选择状态以当前页列表数据为主；数据重载后，仅保留仍在当前结果集中的选中项。
- 回收站视图中隐藏批量逻辑删除按钮，避免语义冲突。

**Backend Design**

- 新增批量请求体 `image_ids: List[int]`。
- 新增接口：
  - `POST /api/images/batch/analyze`
  - `PUT /api/images/batch/delete`
- 批量分析逐条复用单条分析核心逻辑，并对单条失败做结果归档，不中断全批次。
- 批量逻辑删除仅更新指定 ID 的 `is_deleted = 1`，已删除或不存在的记录在结果中返回原因。

**Error Handling**

- 空 ID 列表返回 400。
- 已删除记录不参与批量分析。
- 部分成功返回 `success`，同时附带 `summary` 和逐条 `items`。
- 前端根据 `summary` 弹出可读提示。

**Testing**

- 后端：
  - 批量分析成功路径
  - 已删除记录在批量分析中被跳过
  - 批量逻辑删除仅影响指定记录
  - 部分成功时汇总字段正确
- 前端：
  - 主数据库页存在批量工具条挂载点
  - 存在全选控件
  - 存在批量表征和批量逻辑删除入口
